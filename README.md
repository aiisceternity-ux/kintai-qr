# QR勤怠 × 給与自動計算（Google スプレッドシート + GAS）

QRコードをかざすだけで打刻、月初に前月分の給与を自動集計するシステム。
**ランニングコスト0円**（Google アカウントのみ。外部API・AI一切なし）。

---

## なぜ Notion ではなくスプレッドシートなのか

元ネタの構成（Notion + GAS）と比較した結論。

| | スプレッドシート | Notion |
|---|---|---|
| 集計 | `SUMIFS` / GASで一撃。行が何万行でも平気 | リレーション＋ロールアップは便利だが、API経由の集計は遅い |
| APIレート制限 | 実質なし（GASの内部呼び出し） | 平均3req/sec。打刻ラッシュで詰まる |
| 打刻1件のレイテンシ | 数百ms | 1〜2秒（HTTP往復＋検索クエリ） |
| 障害点 | Googleのみ | Google + Notion の2つ |
| 監査ログ | 追記専用シートを無限に持てる | ページが増え続けてワークスペースが重くなる |
| 給与の再計算 | セルを直して再実行するだけ | ページを1件ずつAPIで更新 |

**Notionが勝つのは「社内のハブがすでにNotionにあり、勤怠を案件DB・シフトDB・評価DBとリレーションで繋ぐ」ときだけ。**
勤怠と給与が独立して完結するなら、スプシの方が速く・安く・壊れにくい。

なお本実装は **`Sheets.gs` だけがデータ保存を担当する** 設計にしてあるので、
後から「やっぱりNotionの他DBと繋ぎたい」となったら、そのファイルだけ差し替えれば移行できる。

## 構成

```
web/scan.html     打刻ページ（GitHub Pages等に置く。カメラを使うのでHTTPS必須）
gas/
  Config.js       設定（休憩ルール・割増率・列名）
  Sheets.js       データ保存層（ここだけがスプシを触る）
  Punch.js        打刻ロジック＋Webエンドポイント（doGet/doPost）
  Payroll.js      月次給与集計・退勤もれ検知・手修正の再計算
  Setup.js        初期化・メニュー・トリガー設置
  scan.html       打刻ページ（GASホスト版。カメラ制限あり／後述）
  admin.html      QRコード発行・印刷画面
  appsscript.json マニフェスト
tools/verify.js   ロジック検証スクリプト（Node、GASサービスをスタブして実走）
```

データの流れ:

```
[QR] → scan.html(カメラ) → POST /exec → Punch.gs
                                          ├ 署名検証（偽造QRを弾く）
                                          ├ 社員マスタ照合（6hキャッシュ）
                                          ├ 当日の行が無ければ「出勤」で追記
                                          └ あれば「退勤」で更新＋実働/残業を確定計算
                                                    ↓
                                  月初4時のトリガー → Payroll.gs → 給与シート
```

### 動作検証

GASにデプロイする前に、打刻と給与計算のロジックだけをローカルで実走できる。

```bash
TZ=Asia/Tokyo node tools/verify.js .
```

署名検証・出勤/退勤・休憩の自動控除・残業割増・締め後の保護・退勤もれ検知まで18項目を確認する。
（スプレッドシート層はスタブなので、シート操作そのものは実機での確認が必要）

## セットアップ（15分）

### 1. スプレッドシートを作る
新規スプレッドシートを作成 → 拡張機能 → **Apps Script**。

### 2. コードを貼る
`gas/` 内のファイルを同じ名前でGASプロジェクトに作成して貼り付ける（`.js` はサーバー上では `.gs` になる）。
- `.gs` は「スクリプト」、`.html` は「HTML」として追加（拡張子は付けない：`scan`, `admin`）
- `appsscript.json` は 設定 → 「`appsscript.json` マニフェスト ファイルをエディタで表示する」をON にしてから貼り替え

> `clasp` を使うなら `clasp create --type sheets` → `gas/` の中身を `clasp push` でもよい。

### 3. 初期化
GASエディタで **`initProject`** を実行（初回は権限承認あり）。
これで以下が自動で用意される。

- シート4枚（社員マスタ / 勤怠ログ / 給与 / 打刻生ログ）＋ 書式・入力規則
- `QR_SECRET`（QR署名鍵）と `ADMIN_KEY` の自動生成
- サンプル社員 A001

実行ログに出る `ADMIN_KEY` は控えておく。

### 4. 社員を登録
「社員マスタ」シートに追記する。

| 社員ID | 氏名 | 雇用区分 | 時給 | 基本給 | 在籍 | QRトークン |
|---|---|---|---|---|---|---|
| A001 | 田中 太郎 | 時給 | 1200 | | ☑ | *(自動)* |
| A002 | 鈴木 花子 | 月給 | | 280000 | ☑ | *(自動)* |

**QRトークンは自動で入る**（編集トリガー、または `issueAllTokens` 実行時）。手で入力しないこと。

### 5. ウェブアプリとしてデプロイ
デプロイ → 新しいデプロイ → 種類「**ウェブアプリ**」
- 次のユーザーとして実行: **自分**
- アクセスできるユーザー: **全員**

→ 発行される `https://script.google.com/macros/s/.../exec` をコピー。

> 「全員」にするのは、スタッフに Google ログインを求めないため。
> **URLを知っていても、正しい署名付きQRが無ければ打刻はできない**（`verifyToken_`）。

### 6. 打刻ページを設置
`web/scan.html` の `API_URL` に 5. のURLを貼り、**HTTPSのどこか**に置く。

- GitHub Pages / Netlify / Cloudflare Pages（すべて無料）
- 動作確認だけなら `python3 -m http.server` → `http://localhost:8000/scan.html`（localhostは安全なオリジン扱いなのでカメラが使える）

```bash
cd web && python3 -m http.server 8000
```

> **なぜGAS上でホストしないのか:** GASのHTMLは二重の sandbox iframe で配信され、その iframe に
> `allow="camera"` が付かないため `getUserMedia` がブロックされる端末が多い。
> `gas/scan.html`（`/exec` を開けば表示される）も同梱してあるので、手元の端末で動くなら
> そちらを使ってもよい。動かない場合は静的ホスティング一択。

### 7. トリガーを設置
GASエディタで **`installTriggers`** を実行。

- 毎月1日 4:00 → `closeLastMonth`（前月の給与を集計）
- 毎日 3:00 → `checkUnclosed`（退勤打刻もれを「要確認」にして通知）
- 社員マスタの編集時 → キャッシュ破棄＋トークン発行

### 8. QRを配る
スプレッドシートのメニュー **「勤怠」→「QRコードを発行/印刷」** → 印刷して配布。
（ブラウザから開きたい場合は `.../exec?page=admin&key=控えたADMIN_KEY`）

## 日々の運用

| やりたいこと | 操作 |
|---|---|
| 打刻 | 打刻ページにQRをかざす。1回目=出勤、2回目=退勤 |
| 退勤時刻を打ち直す | もう一度かざす（最後の打刻が退勤時刻になる） |
| 打刻忘れの修正 | 勤怠ログの出勤/退勤セルを直す → その行を選択 → メニュー「選択した行の実働を再計算」 |
| 給与を今すぐ出す | メニュー「先月分の給与を集計」/「月を指定して給与を集計」 |
| 給与を締める | 給与シートの「確定」にチェック。**以降その明細は再集計で上書きされない** |
| 退職者 | 社員マスタの「在籍」を外す。過去の勤怠と給与は残る |

### 打刻の仕様
- **同じ日の1行目＝出勤、以降の打刻＝退勤**（1日1行）
- 60秒以内の再打刻は無視（二度読み事故の防止、`CFG.COOLDOWN_SEC`）
- `LockService` で同時実行を直列化するので、同じ日の行が二重にできない
- すべての打刻試行は「打刻生ログ」に追記される（偽造QRの検知にも使える）

### 計算ルール（`Config.gs` で変更可）
- 休憩の自動控除: 拘束6h超で45分／8h超で60分（労基法34条）。休憩も打刻運用にするなら `AUTO_BREAK: false`
- 残業: 1日8時間超を 1.25倍
- 実働の丸め: 既定は丸めなし。`'floor15'` / `'round15'` で15分単位
- 深夜勤務: `DAY_BOUNDARY: '05:00'` にすると翌2時の退勤が前日扱いになる

## セキュリティ

- QRの中身は `AT1.<社員ID>.<HMAC-SHA256署名16文字>`。**署名鍵はサーバー側（スクリプトプロパティ）にしかない**ので、社員IDを推測してQRを自作しても弾かれる
- スタッフはスプレッドシートに一切アクセスしない。全員ぶんの給与が見える状況が発生しない
- `QR_SECRET` を変更すると**全員のQRが無効になる**。変更時は `issueAllTokens` → 再印刷が必須

### 防げないこと（正直に）
- **代理打刻**：紙のQRは写真で複製できる。厳密にやるなら端末固定（キオスク端末＋IP制限）やICカードが必要
- **オフライン打刻**：電波が無いと打刻できない（失敗表示になる）。端末側キューは未実装
- **深夜割増（22時〜5時の25%）・社会保険料・源泉徴収**：未実装。給与シートの「支給額」は**総支給額の概算**であり、そのまま振込額にはならない。実際の給与計算は社労士／給与ソフトと突き合わせること

## 想定規模と限界

- 〜50人程度／勤怠ログ数万行までは体感で問題なし
- `findAttendanceRow_` は日付＋社員IDの2列だけ読むので、行数が増えても打刻は重くならない
- それ以上の規模になったら、勤怠ログを年度ごとにシート分割するか、素直にBigQuery/DBへ移す

## トラブルシュート

| 症状 | 原因と対処 |
|---|---|
| カメラが起動しない | HTTPSで開いていない／ブラウザのカメラ許可がOFF。iOSはSafari、AndroidはChrome推奨 |
| 「通信に失敗しました」 | `API_URL` が `/exec` で終わっているか確認。デプロイし直したらURLも変わる（「デプロイを管理」で同じデプロイを更新すればURL固定） |
| 「このQRコードは無効です」 | `QR_SECRET` 変更後にQRを再発行していない |
| 「社員が見つかりません」 | 社員マスタに社員IDが無い／キャッシュが古い → `clearEmployeeCache` を実行 |
| 給与が0円 | 勤怠が「要確認」になっている（集計から除外される）。実働を再計算して「退勤済」に戻す |
